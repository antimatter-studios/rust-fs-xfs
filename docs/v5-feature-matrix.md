# XFS feature and fixture contract

XFS v5 selects checksummed metadata, not a single fixed feature set. The
tables below inventory the flags recognized by `src/superblock.rs`. Bit
assignments are checked against [Linux v6.13's format definitions](https://github.com/torvalds/linux/blob/v6.13/fs/xfs/libxfs/xfs_format.h).
This is a capability contract, not a claim that every checker finding can be
repaired. `fsck.xfs` checks through a read-only mount; `-y` and `-p` fail with
exit 16 before the target is opened. There is no repair implementation.

In the tables, **read** means the mount and the corresponding layout can be
read, **write** means the feature is maintained subject to operation-specific
refusals, and **check** means the existing structural checker can run. A check
does not certify optional metadata that the checker does not inspect. All
rows have **repair = refused** (`tests/cli_dispatch.rs` and
`tests/cli_fsck_oracle.rs` exercise the command-line contract).

## v5 masks

`xfsfeat-NAME.img` refers to a fixture generated by
`scripts/build-feature-matrix-fixtures.sh`. `bits` below means the
fixture-backed `tests/feature_bit_contract.rs`; its source image is opened
read-only and its writable probe panics on any mutation. Tests iterate every
bit in the relevant mask, including reserved and future bits, assert exact
`UnsupportedFeature` messages, and read populated file contents after accepted
mounts. Whole-image SHA256 remains unchanged across the gate and realtime
refusal contracts. CRC-correct overlays use the independently formatted cached
base; they prove gate policy, not pinned formatter provenance (#360).

An unsupported incompat bit prevents both read-only and writable mounts.
An unknown ro_compat bit permits reading and prevents writing. These are
different policies; rejecting every unknown ro_compat bit on read would
violate its format meaning. Overlay tests establish refusal ordering, not
format correctness; real Linux fixtures and xfsprogs remain the format oracle.

## Recognized legacy flags

These fields coexist with v5 masks. Advertised unknown `features2` bits in
either the primary word or historical mirror refuse both mounts before
mutation. CRCBIT is accepted only on v5. Without MOREBITSBIT, the words are
retained and ignored. Every legacy version bit has a defined meaning;
SHAREDBIT is refused, matching Linux's VERSION_OKBITS exclusion. EXTFLGBIT
and DIRV2BIT describe understood layouts. Unit tests cover v4/v5 parsing;
fixture overlays cover mutation ordering and do not establish Linux validity.

## Combination and geometry fixtures

Every listed row is exercised by
`feature_matrix_oracle::every_feature_combination_is_written_correctly_or_refused`.
It starts each operation from a fresh fixture copy, then asks Linux to replay
the journal and `xfs_repair -n` to judge the result. Refusal is distinct from a
successful write. A device wrapper counts writes and requires zero on every
mount or operation refusal. Any unjudged pair fails the run, including one out
of a large matrix; the regression is
`feature_matrix_oracle::even_one_unjudged_pair_fails_the_matrix`.
Each operation's exact expected outcome is declared in
`tests/common/feature_expectations.rs`; unexpected refusals, successful writes
on unsupported rows, and unrelated errors fail. Refusals also require unchanged
whole-image SHA256. `all_feature_fixtures_read_and_check_without_mutation` separately
requires a clean read/check and zero writes for every selected source fixture.

The eleven operation columns are create file, create directory, rename,
unlink, truncate to zero, write into empty file, setattr, truncate shared,
truncate partly shared, convert directory, and create in a later AG. Every
v5 row expects success in every applicable column. The six
non-reflink rows (base, finobt, finobt-inobtcount, rmapbt, rmapbt-finobt,
and rmapbt-finobt-inobtcount) require absent shared-file
operations; every other v5 recipe uses pinned 6.13.0's reflink default.
v4 expects named refusal for its nine applicable operations. quota expects
success in all eleven columns after the independently validated quota-accounting
implementation; this matrix's operation pairs still require CI validation. These are assertions
awaiting independent validation, not evidence of successful Linux writes.

The cached base reproduced four local creation failures: an empty
extent-format attribute fork was incorrectly required to contain block 0.
The reader now recognizes zero attribute extents as empty, following
[Linux v6.13's xfs_inode_hasattr](https://github.com/torvalds/linux/blob/v6.13/fs/xfs/libxfs/xfs_attr.c).
`empty_attribute_fork` exercises the real cached parent directories read-only
and preserves refusal of missing block 0 in nonempty forks and truncated
inode records. The eleven operation expectations remain unchanged. The cache
has no pinned provenance, so independent pinned operation verdicts remain
required.

INOBTCNT requires FINOBT. v5 requires FTYPE. The twelve maintenance recipes
enumerate all three legal FINOBT/INOBTCNT states crossed with both RMAPBT and
REFLINK values. `tests/scripts/feature-matrix-maintenance-combinations.sh`
requires exactly one explicit recipe for each state; formatter defaults cannot
collapse two rows. Encoding and geometry dimensions remain sampled rather than
crossed with every maintenance state. A successful pinned Linux regeneration,
full read/check run, and independent operation verdicts remain required.

## Provenance and reproduction

The feature fixture builder uses the pinned xfsprogs 6.13.0 installed by
`scripts/vm-setup.sh` at `/usr/local/xfsprogs-parent/sbin`. It records the exact
mkfs invocation, tool versions, kernel version, full mkfs output, xfs_info,
xfs_db superblock and root-inode dumps, xfs_repair -n output, quota report,
postformat UUID command, mount options, binary hashes, evidence hashes, and
SHA-256 of the final unmounted image alongside
each fixture. Missing tools, wrong versions, and rejected recipes fail.
Rebuild with `chore fixtures -- feature-matrix`; images and their evidence are
generated under `.vm-share/` and are not committed.

Older images without this evidence cannot establish the pinned provenance.
Retaining a checked-in reference manifest and validating all recorded outputs
against the parser remain required before #359 is complete.
`pinned_feature_geometry_matches_independent_reference` requires pinned
version evidence, final-image hash, matching legacy words, every v5 feature
mask, quota flags, block/sector/inode/directory geometry, stripe dimensions,
and root/user-quota inode numbers. It also requires exact META_UUID, quota,
stripe, and sector geometry. The operation oracle
requires pinned xfs_repair 6.13.0 after Linux replay.

The hermetic builder test checks version and recipe refusals, then exercises
all successful control-flow paths with stand-ins. It verifies each recipe
retains its own image, mkfs output, info, superblock dump, and provenance; this
caught an inner filename loop overwriting the fixture name. Stand-in output
does not establish real formatter or kernel correctness.
